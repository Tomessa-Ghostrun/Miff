# Baseline Profile of Miff, written by hand (no device was available: see android/README.md, "Démarrage").
#
# What it does: AGP compiles this file into the APK/AAB (assets/dexopt/baseline.prof). When the app is installed, the system
# pre-compiles the listed code instead of interpreting it at the first launch, which shortens the very first start (Application,
# first composition, first draw of the launch animation). AndroidX libraries (Compose, Activity, Lifecycle, Navigation, Core)
# ship their own profiles, which AGP merges: this file only lists OUR classes that run between the creation of the process and
# the first screens.
#
# Flags: H = hot (used often), S = used at startup, P = used after startup. Wildcards: ** crosses packages, * stays in one.
# Names are the ORIGINAL ones: with R8 the build rewrites them to the obfuscated names itself.
#
# LIMIT: a hand-written profile lists packages, not the exact methods a real launch calls, so it is less precise than a profile
# recorded with a Macrobenchmark on a device (that needs a device or an emulator and is a follow-up, see the PR). It is
# harmless if a rule matches nothing. The effect only exists in a RELEASE-type build installed through the store or with
# profile installation (the debug APK is not optimised at all, with or without profile).
